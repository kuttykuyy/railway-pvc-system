# Railway PVC System - Project Instructions

## Zone-Based Steel City Pricing (March 2025)

### Architecture
- **Mapping file**: `lib/zone-steel-city-mapping.ts` maps 18 Indian Railway zones to 4 JPC steel cities (Delhi, Mumbai, Chennai, Kolkata)
- **Key exports**: `getRailwayZoneOptions()`, `getSteelCityForZone()`, `getSteelIndexNamesForZone()`, `getZoneDisplayName()`
- **Chennai is default**: Unsuffixed index names (`Steel TMT Bars` etc.) are Chennai rates. For Chennai zones, `getSteelIndexNamesForZone()` returns unsuffixed names (backward compatible)
- **City-specific indices in DB**: `Steel TMT Bars`, `Steel TMT Bars - Delhi`, `Steel TMT Bars - Mumbai`, `Steel TMT Bars - Chennai`, `Steel TMT Bars - Kolkata` (same pattern for Angle/Channel, Plates, Other Sections)
- **Legacy handling**: `getSteelCityForZone()` handles both zone codes (SR, CR) AND legacy city names (Chennai, Mumbai)

### Files Modified for Zone-Aware Steel Pricing
- **Frontend dropdowns**: `bills/new/page.tsx`, `bills/edit/[id]/page.tsx`, `bills/bulk-new/page.tsx` — all use `getRailwayZoneOptions()` 
- **Bill CREATE**: `api/bills/route.ts` — uses `getSteelIndexNamesForZone(zone)`
- **Bill UPDATE**: `api/bills/[id]/route.ts` — uses `getSteelIndexNamesForZone(zone)`
- **Bill RECALCULATE**: `api/bills/[id]/recalculate/route.ts` — uses `getSteelIndexNamesForZone(bill.zone)`
- **Bulk CREATE**: `api/bills/bulk-create/route.ts` — uses `getSteelIndexNamesForZone(billInput.zone)`, saves zone to DB
- **Calculation steps**: `api/bills/[id]/calculation-steps/route.ts` — uses `getSteelIndexNamesForZone(bill.zone)`
- **Diagnostic**: `api/bills/diagnostic/route.ts` — uses `getSteelIndexNamesForZone(billZone)`
- **External bills**: `api/external/bills/route.ts` — uses `getSteelIndexNamesForZone(zone)`
- **PDF report**: `api/bills/[id]/pdf-report/route.ts` — uses `getSteelIndexNamesForZone(bill.zone)`
- **Bulk PDF report**: `api/bills/bulk-pdf-report/route.ts` — per-bill zone-aware indices via `getIndicesNamesForBill(bill.zone)`
- **Abstract report**: `api/reports/abstract/route.ts` — per-bill zone-aware indices
- **Extension compliance**: `lib/extension-compliance.ts` — steel lookups use prefix matching for city-suffixed names
- **PVC calculations**: `lib/pvc-calculations.ts` — `findSteelIndex()` helper does exact match then prefix match

### Important Technical Notes
- `findSteelIndex()` in pvc-calculations.ts is a private helper that checks exact match first, then `baseName + ' - '` prefix
- Extension compliance uses similar inline prefix matching for cappedIndices and indexL_Values
- Bill model has `zone` field (String?, on `bills` table)
- User profile has separate `railwayZone` field (for railway officials)

## Zone-Based Fuel City Pricing (March 2025)

### Architecture
- **Same mapping file**: `lib/zone-steel-city-mapping.ts` — added `getFuelIndexNameForBill(zoneCode, fuelPriceType)` and `getFuelIndexNamesForBill(zoneCode, fuelPriceType)`
- **Key difference from steel**: Unsuffixed `'MPNG Fuel'` = 4-city average (NOT Chennai). City-specific ALWAYS uses suffix, even Chennai: `'MPNG Fuel - Chennai'`
- **Per-bill selection**: Bill model has `fuelPriceType` field (String?, default `'four_city_avg'`). Values: `'four_city_avg'` or `'zone_city'`
- **City fuel indices in DB**: `'MPNG Fuel'` (4-city avg), `'MPNG Fuel - Delhi'`, `'MPNG Fuel - Mumbai'`, `'MPNG Fuel - Chennai'`, `'MPNG Fuel - Kolkata'`

### Fuel Sync
- **Route**: `api/indices/fuel-prices/sync/route.ts` — generates both 4-city average AND per-city monthly indices
- **Auto-creates indices**: `ensureCityFuelIndicesExist()` creates PriceIndex records on first sync
- **Source**: Uses `DailyFuelPrice` model which has per-city columns (delhi, mumbai, chennai, kolkata)

### Files Modified for Fuel Pricing
- Same bill routes as steel (all 10 non-backup routes) + frontend forms
- **PVC calculations**: `findFuelIndex(indexMap)` — mirrors `findSteelIndex()`, exact match then prefix match
- **Extension compliance**: 3 fuel lookups updated with prefix matching fallback
- **PDF report**: Aliasing — city-specific fuel values also stored under `'MPNG Fuel'` key for backward-compatible formula display

### Important Notes
- User must run fuel sync after deploy to populate city-specific monthly indices
- Zone→city mapping is shared between steel and fuel (same `ZONE_STEEL_CITY_MAP`)

## Telegram Bot Integration (March 2025)

### Architecture
- **Webhook endpoint**: `api/telegram/webhook/route.ts` — receives Telegram updates (messages + callback queries)
- **Webhook setup**: `api/telegram/setup-webhook/route.ts` — GET endpoint to register webhook URL with Telegram

### Flow

### Key Differences from WhatsApp
- Uses `chatId` instead of phone number for conversation tracking
- User must manually enter registered phone number to link account (AWAITING_PHONE step)
- Uses HTML parse mode for formatting (`<b>`, `<i>`) instead of WhatsApp markdown
- Uses inline keyboard buttons for selections (callback_query)
- Bot token: stored as `TELEGRAM_BOT_TOKEN` in .env
- Middleware exclusion: `api/telegram` excluded from auth middleware

- Files fixed: `lib/index-status.ts`, `api/indices/latest-available/route.ts`, `api/indices/validate-date/route.ts`, `api/indices/available-final-months/route.ts`, `api/indices/available-date-range/route.ts`

## PDF Component Document Deduplication Fix (March 31, 2025)

### Issue
- When bills used multiple steel types (TMT, Angle/Channel, Plates, Other Sections) or when multiple component types referenced the same JPC document, the same document was embedded multiple times in PDF reports.
- Example: A bill with TMT, Angle/Channel, and Plates would embed the JPC document 3 times if all referenced the same physical file.

### Root Cause
- If the same physical JPC document was uploaded/stored with different component type labels, or referenced under different component types, it would be embedded once per component type.

### Solution
- Added deduplication by `cloudStoragePath` in two functions:
  - `embedComponentIndices()`: Single bill PDF reports
  - `embedComponentIndicesRange()`: Bulk/multi-bill PDF reports
- Creates a Map keyed by cloud storage path to ensure each unique physical document file is embedded only once
- Added informative logs: "X total documents, Y unique by file (deduped by cloud storage path)"

### Files Modified
- `lib/pdf/utils/labour-index-embedder.ts`:
  - Both functions now deduplicate by cloud storage path before embedding
  - Simplified sorting logic by removing nested component type grouping
  - Direct iteration over deduplicated documents

## Telegram Contract Creation (April 1, 2026)

### Overview
- **Feature:** Full contract creation via Telegram bot (previously only bill creation)
- **Command:** `/createcontract` (also accepts "create contract", "new contract", "contract")
- **Process:** 6-step interactive conversation with user validation and confirmation

### Contract Creation Conversation Steps (in order)
1. **AWAITING_AGREEMENT_NO** — Enter unique agreement number (2-50 chars, uppercase)
   - Validates: length, uniqueness check against existing contracts
   - Example input: "AG-001" or "LOA-2025-123"

2. **AWAITING_CONTRACTOR_NAME** — Enter contractor name (2-100 chars)
   - Example input: "ABC Construction Ltd"

3. **AWAITING_WORK_DESCRIPTION** — Enter work description (5-500 chars)
   - Example input: "Railway bridge construction"

4. **AWAITING_OPENING_DATE** — Enter date of opening in DD/MM/YYYY format
   - Validates: date format and validity
   - Example input: "15/03/2025"
   - Auto-calculates baseMonth as one month prior

5. **AWAITING_LOA_NO** — Optional LOA number (2-50 chars)
   - User can type "SKIP" or "S" to skip
   - Example input: "LOA-2025-001"

6. **AWAITING_CONTRACTOR_PHONE** — Optional contractor phone (10-12 digits)
   - User can type "SKIP" or "S" to skip
   - Example input: "9876543210"

7. **CONFIRMING_CONTRACT** — User confirms summary before creation
   - Shows all entered data in formatted summary
   - User must reply "YES" or "NO" to confirm

### Implementation Files
**File:** `lib/telegram-message-handler.ts`
- `startContractCreation()` — Initiates contract creation flow
- `handleAgreementNo()` — Validates and stores agreement number
- `handleContractorName()` — Validates and stores contractor name
- `handleWorkDescription()` — Validates and stores work description
- `handleOpeningDate()` — Validates date and calculates base month
- `handleLoaNo()` — Validates and stores optional LOA number
- `handleContractorPhone()` — Validates and stores optional phone
- `handleConfirmContract()` — Routes to creation or cancellation
- `createContractFromTelegram()` — Creates contract via Prisma
- `sendConfirmContractSummary()` — Displays confirmation message
- `getBaseMonthFromOpeningDate()` — Helper to calculate base month

**File:** `lib/telegram-conversation.ts`
- Added new TelegramStep enum values for contract creation
- Updated TelegramConversationData interface with contract fields:
  - `agreementNo`, `contractorName`, `workDescription`, `dateOfOpening`, `loaNo`, `contractorPhone`

### Database Creation
- **Method:** Direct Prisma `contract.create()` instead of API call
- **Fields set automatically:**
  - `userId` — From linked Telegram conversation
  - `baseMonth` — Calculated from `dateOfOpening`
  - `pvcApplicable` — Set to `true` by default
- **Optional fields:** `loaNo`, `contractorPhone` (can be null)
- **Required fields:** `agreementNo`, `contractorName`, `workDescription`, `dateOfOpening`

### Error Handling
- **Duplicate Agreement Number:** Checked before form starts (step 1)
  - Provides specific error: "A contract with Agreement Number 'X' already exists"
- **Prisma unique constraint violation (P2002):** Caught and handled gracefully
  - User receives friendly error message
  - Conversation resets for retry

## Steel PVC Forecast Feature (May 2025)

### Overview
- **Page**: `/pvc-forecast` — analyzes steel price index trends to help contractors plan work timing
- **API**: `/api/pvc-forecast` — fetches index data and calculates quarterly PVC impact
- **Purpose**: When steel prices drop below the base index (tender closing), steel PVC becomes negative. This feature shows contractors which quarters are favorable (positive PVC) vs unfavorable (negative PVC) for steel work.

### How It Works
1. User selects a contract (or manually enters base month) + railway zone + steel type
2. API fetches the base month index value and all subsequent monthly values
3. Calculates quarterly averages and compares to base index
4. Shows PVC per ₹1 lakh of steel work for each quarter

### Implementation Details
- **API Route**: `app/api/pvc-forecast/route.ts` — uses `prisma.priceIndex`, `prisma.monthlyIndexValue`, zone-steel mapping
- **Page**: `app/pvc-forecast/page.tsx` — client component with Suspense wrapper for useSearchParams
- **Charts**: Uses recharts (AreaChart for trend, BarChart for quarterly PVC impact)
- **Navigation**: Added to both desktop and mobile navigation under "Contract Management"

### Key Features
- Summary cards: base index, latest index, positive/negative quarter counts
- Best/worst quarter advisory cards with actionable guidance
- Monthly index trend chart with base line reference
- Quarter-wise PVC impact bar chart (green=gain, red=loss)
- Detailed breakdown table with all quarter data
- Advisory note explaining how to use the forecast
